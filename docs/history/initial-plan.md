# RoboFrontier 最小可运行版本计划

状态：2026-10-19 已交付第一阶段 Human 键盘练习版；依赖、Panda 场景、末端 IK / 关节控制、初态恢复、录屏和三次参考抓取验证已完成。实际运行方法与范围以 README.md 为准。本文余下内容保留为后续完整实验原型的计划，工具接管、step 协议与正式 RGB / Oracle 隔离尚未实施。

## 交付范围

先交付一个本机 MuJoCo 桌面窗口：Panda 7 DoF、桌面、红蓝绿三个自由方块、固定相机、键盘遥操作、恢复初始场景、MP4 录制和动作日志。用户先操作；之后 Codex 通过本地命令接口操作同一个运行中的仿真。

第一版不建设网页、实验矩阵、统计报表、配对播放器或独立 GPT API 客户端。先证明真实接触抓取可用。

## 技术路径

- Python 3.12 项目独立虚拟环境，锁定实际验证通过的依赖版本；不修改系统 Python。
- MuJoCo + Menagerie 的 `franka_emika_panda` 模型；只获取必要模型和资产，记录上游 commit 和许可证。
- MuJoCo 原生 `mjv` / `mjr` 渲染 + GLFW 小窗口。窗口和 OpenGL 位于 macOS 主线程，直接接收按下、松开、焦点变化。这样可以可靠实现多键输入，不依赖全局键盘监听或访问 passive viewer 的私有窗口。
- NumPy 实现小型阻尼最小二乘 IK；保留官方位置伺服执行器，不引入 ROS / robosuite。
- FFmpeg 编码视频。物理推进、输入和编码解耦，编码繁忙不能改变动作时长或物理步长。
- 运行中的仿真提供仅绑定 `127.0.0.1` 的本地命令服务；CLI 是它的客户端。只有仿真线程可以修改 `MjData`。

以下是待验证的工程起始值，不是真机参数标定结果。所有值集中在一份配置里；验收后冻结。

| 项目 | 初值 / 规则 |

| 机器人底座 | 固定在世界 (0, 0, 0.40) m；桌面覆盖底座和抓取区域 |

| 重力 | (0, 0, -9.81) m/s² |
| 步长 | 0.002 s，500 Hz；不因为窗口掉帧增加步长 |
| 控制更新 | 100 Hz；每个控制周期 5 个物理步 |
| 渲染 / 视频 | 屏幕目标 60 FPS；固定相机视频 1280×720、30 FPS |

| 接触 | 开启物体、桌面、夹爪与模型定义的机械臂碰撞；保留上游自碰撞排除关系 |
| 方块接触起点 | friction=(1.0, 0.005, 0.0001)，condim=4；实际接触参数以 geom/pair 合成结果核验 |
| 机器人动力学 | 保留上游质量、惯量、关节阻尼、执行器 PD 增益和力矩限制；不随意放大夹持力 |

三色关系暂时只有固定布局，正式 R0/R1 试验前再定义 camera-left / world-left 并做多种子布局，避免歧义。

打开时先在固定控制参考下运行约 1 s 使接触稳定；检查穿透、漂移、初始夹爪间距和可达性，再把稳定后的状态保存为 episode 初始快照。不把随意填写的初始关节角当作已验证配置。添加 freejoint 后重新构造 keyframe，不能直接沿用只有机器人时的 qpos 长度。

## 键盘控制

### 默认：末端移动，方便实际抓取

夹爪默认保持朝下；箭头沿世界 X/Y 平移，W/S 沿世界 Z 上下，A/D 调整夹爪 yaw。界面标注对应正负方向，固定相机和坐标轴一起用于校准直觉。

- 平移慢 / 正常 / 快：0.01 / **0.03** / 0.06 m/s。
- yaw 慢 / 正常 / 快：5 / **15** / 30 °/s。
- 多方向同时按下可斜向运动；合成后的平移向量按总速度限幅，不能因为按三个键就变为根号三倍速度。
- IK 输出仍受七个关节各自的速度、加速度、位置和执行器力矩限制；接近奇异点或无法继续移动时停止积累目标并显示原因。
- 默认不开放任意 roll/pitch，降低首轮键盘操作负担。

### 关节模式：可以独立或同时控制七个关节

Tab 在末端 / 关节模式间切换，并清空所有按键和旧速度指令。

| 关节 | 正方向 / 负方向 | 默认命令速度 | 慢 / 快 |
| --- | --- | --- | --- |
| J1 | Q / A | 15 °/s | 5 / 30 °/s |
| J2 | W / S | 15 °/s | 5 / 30 °/s |
| J3 | E / D | 15 °/s | 5 / 30 °/s |
| J4 | R / F | 15 °/s | 5 / 30 °/s |
| J5 | T / G | 15 °/s | 5 / 30 °/s |
| J6 | Y / H | 15 °/s | 5 / 30 °/s |
| J7 | U / J | 15 °/s | 5 / 30 °/s |

- 七个关节均可同时给出命令，实际按键组合受键盘硬件 rollover 限制；界面显示识别到的键与速度向量。工具接口可以完整发送七维向量。
- 同一关节的正负键同时按下，相互抵消；不同关节不相互覆盖。
- `[` / `]` 在慢、正常、快三档之间切换；窗口显示当前档位和每关节命令速度、实测速度。
- 七关节参考加速度初值均为 60 °/s²；内部统一 rad 和 rad/s。配置允许分别设置，首版采用相同的保守值。
- 位置软限位采用模型 joint range 和 actuator ctrlrange 的交集，并预留 0.02 rad 余量；接近边界提前减速，不靠碰到硬限位停止。
- 上述速度是我们定义的**参考轨迹速度**。上游执行器是位置 PD，并不存在可直接照搬的“默认运动速度”；碰撞、负载和控制误差都会使实测速度不同。超速或跟踪误差异常时终止当前动作并记录，不能把参考限幅说成真实速度硬保证。

### 通用操作

- O / P：打开 / 关闭夹爪。默认总开口从约 80 mm 到 0 mm，用约 1 s 的参考斜坡完成；遇到物体不要求实际开口归零。遵循上游夹爪 actuator 0…255 的映射。
- Space：立即暂停物理并清除指令；再次恢复时从当前姿态保持，不能继续执行旧按键。
- Backspace：结束当前 episode，恢复冻结的初始状态并新建 episode；录制中先关闭旧视频，不把 reset 前后拼成同一条轨迹。
- F9：开始 / 停止录像；Esc：正常保存并退出。
- 松键：撤销该方向的速度请求，受限减速后保持。窗口失焦：清除按键并暂停，防止漏掉 key-up 后持续运动。
- 无持续动作排队；卡顿时不把旧按键累积成大量延迟动作。

## 同一个控制内核，两种时间使用方式

第一轮给用户的是实时练习模式，按住就动、松开就停；物理在无输入时也持续推进，物体可以自然滑动或掉落。

同时保留 step 模式，用于之后 Human/GPT 的可比较操作：默认每条动作推进 0.20 s 仿真时间，允许 0.10…1.00 s，按 0.01 s 对齐。动作结束后冻结仿真并返回观测；下一条动作才继续。`wait` 也是显式动作，夹爪也需要物理推进时间。

键盘在 step 模式下先组合方向 / 关节向量，Enter 提交一条动作；双方使用相同 duration、相同速度与限位、相同观测更新规则。实时练习日志显式标记为 practice，不能直接宣称与逐步 GPT 操作是公平实验。

## Codex 如何接入、输出什么、谁执行

执行链为：

```text
键盘事件 ──────────┐
                  ├→ Action → 校验 / 限幅 → 动作调度 → 控制器 → mj_step
Codex 的本地 CLI ─┘                                      ↓
                                                  观测 / 日志 / 视频
```

Codex 不通过聊天文本直接驱动关节，也不使用“重启脚本再跑动作”的方式。持续运行的仿真进程拥有唯一状态；CLI 仅提交 JSON 并等待结果。

共同 Action 合同：

```json
{
  "request_id": "episode001-action004",
  "expected_observation_id": 3,
  "type": "joint_jog",
  "velocity_rad_s": [0.0, 0.12, 0.0, -0.08, 0.0, 0.0, 0.0],
  "duration_s": 0.2
}
```

其他动作：`tcp_jog(linear_m_s[3], yaw_rad_s, duration_s)`、`gripper(open|close, duration_s)`、`wait(duration_s)`、`observe()`。reset / 录制属于 session 管理动作，与机器人任务动作分开记录。

执行器检查字段、长度、有限数值、时长、当前控制所有者和 observation_id。非法输入拒绝；合理输入的限幅要显式返回；request_id 去重，避免超时重试导致重复动作。Human / Codex 互斥接管，切换时清空指令并回到保持状态。

当前 Codex 已有命令执行和图片查看工具，因此最短接法是：

1. Codex 用现有命令工具调用项目 CLI，例如 `uv run python -m robofrontier.cli action --json-file action.json`。
2. CLI 将请求发送到运行中的本地仿真服务；服务放入有界队列，仿真主线程执行，网络线程不触碰物理状态。
3. 共享控制器生成平滑关节参考，由 MuJoCo 的位置执行器产生力矩；物理引擎执行接触与运动。
4. 动作结束返回 JSON：request_id、实际执行时间、限幅 / 错误、最新 observation_id、机器人状态、RGB 图片绝对路径、日志路径。任务失败和通信失败分开。
5. Codex 通过现有图片工具读取这张图，再决定下一条动作。首轮是 Oracle 调试，后续 RGB 视图过滤物体真值；内部日志仍保存完整真值。

这已经是真实的工具闭环，不需要先申请 GPT API key。日后若需要独立 GPT 程序，再把同一 Action 包装成 function tool / MCP；注册工具本身不会执行物理，执行仍由本地仿真进程完成。当前聊天不会凭空出现一个新注册的 robot MCP 工具。

## 初始化、记录与录屏

每次 episode 保存：模型与依赖版本、配置及其 hash、seed、固定相机内外参、task、操作者、控制模式、初始物理快照和控制器状态。

reset 不仅恢复 qpos，也恢复 qvel、act/ctrl、仿真时间、积分所需状态、外力、控制器参考与滤波状态；清空输入、队列、上一动作、成功计时器，重新生成 observation_id。使用 MuJoCo state API 存取相应积分状态，并重新 forward；版本和状态布局必须匹配。

每条动作记录提交值、实际限幅后的值、前后状态、耗时、返回观测引用和错误。额外保存视频采样时刻的状态快照，用于重渲染；跨引擎版本或平台不承诺逐位相同的重新仿真。

录屏默认录 MuJoCo 固定相机画面和模式 / 速度 / 仿真时间 / 动作编号 HUD，不依赖 macOS 桌面录屏权限。输出 MP4、JSONL 和状态快照到同一个 episode 目录。实时练习视频按 wall time 展示操作节奏，step 视频按 sim time 展示动作，文件元数据明确时间基准；等待思考时间单独记录。编码异步且队列有界，发生丢帧必须记录并报告。

## 实现顺序及每步验收

1. **先让窗口出现**：独立环境、锁依赖、下载指定模型、桌面三方块、固定相机。无输入运行 30 s，无数值发散和明显物体漂移；确认桌子和机器人没有初始穿透。
2. **控制可用**：先做共享关节轨迹和夹爪，再接键盘与小型 IK。检查单关节、多关节、变速、松键、失焦、软限位、暂停和恢复；默认末端控制能可靠接近方块。
3. **验证真实抓取**：一个确定性的参考动作序列只用共享 Action，完成靠近、下降、闭合、抬升；固定初态重复 3 次。目标中心抬高至少 5 cm、在重力下保持至少 1 s，并核对双指接触；此判定须通过推进物理完成，暂停不计保持时间。若失败，先排查模型 / 控制 / 接触，不用吸附掩盖问题。
4. **用户可操作并保存**：验证 reset 的完整状态一致性；键盘从初态完成一次抓取；F9 产生可播放 MP4、动作日志和快照；退出正常封装视频。
5. **打通之后的接管入口**：本地 CLI 提交 observe / joint_jog / tcp_jog / gripper / wait，检查与键盘调用相同执行器，验证 request_id 去重和观测版本检查；在 step 模式完成一次参考序列。

第一版完成标准是以上五步均通过，并在 README 给出一条启动命令、键位表、参数位置、录屏位置和接管方法。正式 Human/GPT 实验、额外布局与论文指标在这之后开展。

# Mosaic R13 Oracle worktree

This branch owns mosaic adapters, mosaic tests and mosaic run protocols. Shared
controller/evaluator/recording changes require explicit review before merging;
other task worktrees are not modified here. Main and dial branches are retained.

## Inputs and run identity

Use configs/suites/frontier-mosaic-r13.json and the unchanged pd1000-v1 control
profile. All nine environments have independent COW materialized assets in this
checkout. Runtime dependencies and existing runs/outputs are external links.
Write each new experiment into a unique mosaic namespace. Freeze the clean Git
commit, complete executor source, harness/catalog and actual scene/asset hashes.
Historical unit witnesses retain their own source versions; they are not HEAD
Oracle successes. Never infer an artwork pass from independent one-cube units.

## Task and manipulation freedom

The full Oracle must reproduce the supplied pattern using the original evaluator.
Inventory provenance does not assign exclusive robot ownership. Direct airborne
handovers, stable central staging and other safe tabletop staging are allowed.
L1 central staging must account for real pocket floors/walls; L2/L3 can use the
central empty tabletop. No mandatory routes, transfer pairs or buffer fixtures.
Preserve completed placements. A program's finite buffer search is a strategy,
not a new restriction on the task or future GPT policy.

Only actuator commands and real contacts change the live world. No hand welds,
object state writes, in-episode resets or runtime physics/evaluator edits.
A rejected candidate is not physical infeasibility. Unknown execution is recorded
and not blindly replayed; a new independent engineering attempt is declared and
keeps the previous evidence. Physics records stay60Hz for offline reconstruction.

## Sequence and bounds

Run a full72-goal four-arm L1 pilot from a committed frozen source first. Budget:
1800wall seconds,8000simulation seconds,20000action batches. Record failures and
stop a failed attempt rather than silently reset. A bounded unit continuation may
run beside the pilot; mosaic uses at most two physical instances initially.

After a clean full pilot, qualify remaining difficulties/scales with bounded
supervision. Recheck final acceptance and unresolved actions at shutdown. Formal
GPT evaluation follows integration/regression and a new frozen run version;
exploratory branch results must remain labeled by their actual commit.

# 多机械臂 LLM agent 通信：论文证据与可验证假设

调查时间：2026-10-29。本文只总结公开论文及其对本项目的**研究假设**；不是已验证实现或已证明能改善 RoboFrontier 的结论。

## 最相关论文

1. [Chen 等，Scalable Multi-Robot Collaboration with Large Language Models: Centralized or Decentralized Systems?（ICRA 2024）](https://arxiv.org/html/2309.15943v2)：比较单个集中规划器、每机器人分布式 agent 以及两个混合架构。其 HMAS-2 由中心提出方案，相关机器人给反馈，中心按反馈修订；只有参与行动的 agent 参与当前讨论。作者在四种 2D 协作场景及部分 3D 模拟中报告混合架构效果和扩展性更好；历史信息对照中，状态—动作历史在其设置里取得较好的成功率与 token 权衡。限制：该论文规划和通信是迭代轮次，含全体一致的方案，并非本项目持续实时物理操作；其评价计入碰撞等失败，不能直接换算本项目终态评分。**启示**：对涉及的 Worker 定向沟通，Coordinator 获取本地反馈；避免每个动作都走全队确认；简洁状态摘要需保留未解决承诺。
2. [Zhang 等，Building Cooperative Embodied Agents Modularly with Large Language Models（CoELA，ICLR 2024）](https://arxiv.org/html/2307.02485v2)：研究分布式控制、原始感知、通信成本与长期多目标任务；CoELA 模块包括记忆、规划和通信，将发送消息作为可选动作；论文分别在 C-WAH 和 TDW-MAT 环境中评估。限制：环境和低层动作与 MuJoCo 多臂接触不同，不能推断增加模块即有效。**启示**：消息发送由 agent 依据局部需要选择，按需提供过去观察、动作与未完成承诺，不把所有对话直接广播。
3. [Li 等，Improving Multi-Agent Debate with Sparse Communication Topology（EMNLP Findings 2024）](https://aclanthology.org/2024.findings-emnlp.427/)：在 GPT 和 Mistral 的多 agent 辩论中，稀疏通信拓扑取得与较密拓扑可比或更好的表现，并降低计算成本。限制：研究对象是辩论、推理和多模态对齐，并非实时物理合作；稀疏图不保证涉及共享物体的机器人能协调。**启示**：为 peer 测试定向通信与有界消息，不应将全广播视为默认更优；必须为真正受影响者保留沟通路径。
4. [Khatana 等，Verifier-Mediated Multi-LLM Coordination for Multi-Robot Path Planning（2026 预印本）](https://arxiv.org/html/2610.12761v1)：用几何验证器检查多机器人候选轨迹，给相关 agent 反馈预计冲突的对象、位置和时间；实验为 CARLA 与 Crazyflie。限制：研究导航、使用特定规划/验证器，不是视觉抓取，更不能把预测当成连续物理安全证明。**启示**：可探索自愿调用、明确覆盖范围与不确定性的候选运动检查；不得把私有真值或裁判结果传给策略，也不得把现有 advisory 检查说成碰撞保证。
5. [Pappu 等，Multi-Agent Teams Hold Experts Back（ICML 2026）](https://proceedings.mlr.press/v306/pappu26a.html)：在人类启发任务和机器学习基准上研究自由组队，报告其设置中的团队常未达到最佳个体水平，且讨论中存在稀释专业意见的倾向。限制：不属于多臂操作，也不能证明本项目中 single 必然更好。**启示**：应保留公平的 single 对照；agent 更多、沟通更充分均不是性能保证。

## 可检验的设计方向

- **可靠性先行**：建立并验证三个模式的正确启动、身份/控制权、收件传递、结束与持久记录。否则观察到的卡住无法区分模型能力与基础设施失败。
- **共享信息最小化**：团队默认只传播跟接收者工作相关的可公开信息；消息建议包含范围、证据来源/时间、下一次可行动的条件和释放条件，但自由文本能表达不同事项，不能因必填字段导致任务卡死。该模式改变提示，须版本化并与现有方案对照。
- **非阻塞协商**：某个共享资源等待期间，agent 仍可以执行不冲突的局部任务；针对有交集的 agent 协调，而非全队审批。该思路与当前 skill 已有规则相近，重点是验证实际会话是否遵循，而不是假定缺少这一功能。
- **易丢信息的摘要**：若增加摘要，只使用 agent 合法看过的信息；保留仍有效的约束、动作状态、版本/时间、未解决请求和不确定性，并保留原始消息与溯源。防止摘要过时、覆盖冲突或将他人推测当事实。摘要是否自动生成、是否额外消耗 token 必须对照测试。
- **建议与自动规划的边界**：不会由系统偷偷分配抓放路径、指定执行策略、引入 Oracle 信息。任何共享公告栏、调度助手或自动推导冲突，若改变可见信息或角色自由度，都是新的实验协议，不能当作原版结果直接混合。

## 对照与指标

任务、资产、初态、可见信息、物理和评分保持一致；公开启动和读题时间计入方式统一，配置与 prompt 版本写入 manifest。每种 topology 独立世界；Dial 比较使用经声明的相同实例，不把私有答案公开给 agent。先离线确定消息身份、接收、去重、交错、动作不确定性、停轮和终止语义，再进行少量有界真实运行。测每种模式下成功/终态进度、墙钟时间、token/费用、消息数/长度、端到端投递及唤醒延迟、等待/阻塞、执行重叠、过程事件及系统失败；多 seed 重复并报告缺失和不确定性。实践限制：不同模式本质上拥有不同角色、上下文继承与消息图，无法让所有条件完全相同；应明确比较的是完整协作系统，而不是声称只改变一项变量。

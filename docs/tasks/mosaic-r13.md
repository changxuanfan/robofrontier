# Mosaic R13：最终任务规格与 GPT 审查包

Mosaic 九个完整 Oracle 已通过，合计1566格；原始场景、执行记录和成功证据保持
不变。本任务包把公开静态规格、完成规则与操作说明整理出来，供合并后的 GPT
准备链加载。**它是审查包，不是已经解锁运行门禁的 GPT run。**

## 唯一的家族入口

使用 `configs/task_families/mosaic/r13.json`，显式绑定
`configs/suites/frontier-mosaic-r13.json` 的九项。当前通用 `v2.cases()` 和旧的
minimum-policy-batch 脚本可能选择 R10，不能代替此入口。

| 机械臂 | 网格 | 各等级目标格数 | 冻结环境声明的桌面外尺寸（m） |
|---|---|---:|---|
| 4 | 6×12 | 72 | 2.465×2.66175 |
| 6 | 9×18 | 162 | 3.0725×3.41125 |
| 8 | 12×24 | 288 | 3.68×3.3435 |

台面高度均为0.8m；每个 case 的基座、朝向、实际工作范围和静态相机参数分别
写入生成的公开 task.json。桌面描述还要与 L1 口袋的局部几何一起理解，不能把
整个外轮廓当作无开口的连续支持面。无需记住另一项实验的坐标。

## 图案、供料与等级

方块边长60mm、格距81mm。四种颜色为 cream、navy、coral、sage；图案矩阵和
生成参考图已经按世界北向上摆好，第一行在+Y、第一列在−X。历史“整图旋转90度”
或“9×18镜像”描述是制作参考图的过程，GPT应直接使用提供的成品参考，避免再
操作一次。背景色格也计入目标。

供料标签和初始颜色数量不建立排他所有权；目标以颜色匹配，不要求固定来源的
方块。可以按可达性、抓取通道、干涉与处理次数选择分工、顺序、交接和暂存。
没有固定机器人配对、强制传递路线或固定颜色顺序。

- L1：80mm净开口的真实方口袋，深20mm；需要整个旋转后的方块投影容纳并坐底。
- L2：3mm红色印刷线，没有把方块锁定的物理网格约束。
- L3：没有可见网格，目标图案与声明的装配坐标系仍有效。

## 与当前裁判对应的完成条件

数值的机器来源为家族 registry 的 completion，测试直接调用现有私有裁判验证
这些边界；原裁判代码不在本次修改范围内。

| 条件 | 判据 |
|---|---|
| 覆盖 | 每格一个不同的正确颜色方块，全部格最终同时合格 |
| 释放 | 方块与机器人几何没有距离≤0.2mm的接触；发出open指令本身不等于释放 |
| 稳定 | 线速度严格小于0.01m/s、角速度严格小于0.1rad/s，连续满足1个仿真秒 |
| 朝向 | 方块轴与工位轴对齐误差≤8度，允许方块自身90度对称等价 |
| L2/L3位置 | 中心xy欧氏误差≤5mm，中心z误差≤3mm |
| L1位置 | 完整旋转投影位于口袋净开口内，包含余量0.3mm；底面高度误差≤0.8mm，并有≤0.2mm坐底接触 |
| 过程 | 最终全部格合格还需无过程违规；可记录失败后在原世界合法恢复，不把失败记录删除 |

L1不是“中心必须5mm内”。框定中心、抓持偏移、张爪空间与安全撤退需要分别判断；
后来碰触成品可能使资格失效，需要观察受影响的格。容差与命令终止阈值是不同
层次，READY/工具反馈仍是实际可执行能力的来源。

## 公开材料与工程证据

生成目录的 `public/` 只含：九份 task.json、九张目标图、Mosaic任务prompt和
独立Mosaic skill。公开任务补齐静态桌面/方块/相机/机器人规格、完成条件、供料
汇总和已经公开的目标矩阵。实时物体真值、Oracle目标—物体分配、动作序列、修复
recipe及执行快照不导出。

`engineering/` 保存版本、逐项Oracle/audit/stream/资产hash、实际辅助与失败标记，
用于工程审查；不是 policy 的初始经验。当前9项冻结 harness 都与 servo2相同，
使用pd1000-v1；裁判源码也与各次选中执行一致。源码、资产、控制或证据变化会使
检查失败，不能靠把旧 task 的 oracle_verified 改true恢复。

共享角色prompt、通用robot-collaboration skill、READY/动作接口和正式门禁保持
原样。未来共享装载器应从本包选择公开材料，冻结入新run，并登记其hash；不能
在旧run封存后偷偷添加文件，也不能假装为旧bounded probe。

## 构建和检查

```sh
python -m scripts.build_mosaic_policy_package \
  --output outputs/policy-packages/mosaic-r13-20261027 \
  --verify-recorded-chunks

python -m scripts.build_mosaic_policy_package \
  --output outputs/policy-packages/mosaic-r13-20261027 --check
```

新目录必须不存在，避免覆盖已审查输入。构建/检查不创建run、不调用模型、不推进
物理、不改变源文件。默认接受已绑定的完整动作审计并校验资产；显式选项会额外
复查所有原始动作块校验和。公开文件多出、少掉、被改动、图片方向/颜色不一致、
甚至重新封存后仍夹带私有字段或符号链接，都会拒绝。

## 合并阶段待办与工厂播放边界

本次只落Mosaic专有材料/检查器。共享 readiness 注册、public投影扩展、专项
prompt/skill载入与run封存需要合并时统一实施，完成前 policy_launch_ready=false。
GPT模型、topology、观察及费用/运行协议届时单独冻结。旧pilot/probe期限不继承。

Mosaic展示默认30倍速/30fps，原始轨迹60Hz。此偏好不改变物理控制，也不替其他
家族决定倍速。当前已交付去静止时间表可跨背景复用，但多桌独立时钟和长期明显
无任务作用的振荡识别仍是单独工作项，不能以本任务包的完成宣称它们已实现。

多工位最终采用：各桌独立跳过自己的无用区间、统一渲染工厂；先完成的桌子保持
最终成品，允许完成后静止，不循环。持续抓持/支撑可能有作用；姿态和力设定不
等于完整实测接触力。已记录的公开/私有数据边界也适用于未来去无用段分析结果。

## Mosaic私有轨迹审查产物

```sh
python -m scripts.audit_mosaic_motion_intervals \
  --output runs/engineering/mosaic-motion-review-20261027 --workers 3
```

参数在 `configs/task_families/mosaic/motion-review-r13.json`。它先保护真实动作、
有记录的力持握、进展/拾取/释放和完成事件，再检查剩余长空闲窗口。微幅颤动可
成为idle提议；明显重复的物体/夹爪/关节振荡可标记待审查；慢净位移与非重复
物体运动保留。未知/失败的张爪不会被假设为已经解除持握。

本次九项分析得到135个proposed_idle_cut、5个keep_slow_net_motion；三个4臂
案例没有长空闲候选。真实候选中未检出review_repeated_*，该分支通过了合成
振荡样例验证。没有修改任何现有edit或视频，也没有宣称实测机械力为零。具体
源区间、动作/进展保护、hash和标签位于独立工程报告，不进入公开任务包。

公共整合接口及验收见同目录 `mosaic-shared-integration.md`。

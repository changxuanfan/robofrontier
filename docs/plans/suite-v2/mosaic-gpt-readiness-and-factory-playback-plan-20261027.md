日期：2026-10-27（Asia/Hong_Kong）。本文件记录原始规划。

执行进展：用户随后授权“开始”；Mosaic专有任务包、独立skill/prompt、规格/证据检查器与
私有轨迹候选审查器已实施。共享harness、运行门禁、公开材料装载和多桌播放器未修改。
当前入口见 `docs/tasks/mosaic-r13.md`，共享待办见 `docs/tasks/mosaic-shared-integration.md`。
下面“本轮只规划”等文字描述规划时点，不撤销后续实施授权。
本文把本次语境中的 worksheet 理解为任务家族对应的 Git worktree。
本轮只新增本文，不修改任务、prompt、Skill、harness、裁判或回放实现，不准备/启动
GPT run、不重跑 Oracle、不合并分支，也不修改其他家族 worktree。

用户已明确：**工位先完成后保持最终成品，允许完成后静止，不循环播放。**
需要删掉的是任务进行中的无用等待/抖动，不是完成后的成品展示。

## 1. 最终目标与当前判断

目标 A：正式 GPT 仿真读到的工位、任务规则、工具能力、公开输入和裁判，必须与
最终确定的任务版本一致。各家族只维护自己的规格、说明和适配；公共基础设施由
合并阶段统一实现一次。

目标 B：工厂同时展示多个已完成 Oracle 的轨迹时，每桌独立跳过已确认的无用
区间，直接从原始状态取帧，再把各桌状态组合到同一画面。无需重新求解物理，
不依赖渲染后裁剪整段工厂视频。每桌有自己的源时间和剪后时间。

**现有交付只部分覆盖目标 B，不能称为全部做好。** Mosaic 已有与原始60Hz记录
绑定的30倍速/30fps逐帧映射、完整采样率保留窗口、单工位工厂回放和匹配工位。
但本 worktree 没有完整的多工位独立时钟编排；现有静止检测也没有证明能识别
“幅度明显、持续很久、但没有有效任务作用的振荡”。当前映射还包含简单场景画面
判定的结果，不是已经完成的、与机位无关的物理有效动作分类器。

Mosaic 原始九项完整任务及独立记录审计已完成，累计1566目标；这是带特权状态
及辅助恢复的 Oracle 证据，不等于 GPT 策略验证。其他家族应引用各自最终选中
证据，不由本分支代为宣布就绪。

## 3. Mosaic 自有任务包：后续可在本分支做的内容

建议新增以下家族专有文件；**本轮不创建这些实现文件**：

- `configs/task_families/mosaic/r13.json`：九项版本与证据索引、规格版本、引用hash、
  控制指纹、裁判版本、辅助/失败标记、30倍速展示默认。
- `docs/tasks/mosaic-r13.md`：人的最终任务说明与逐级差异。
- `prompts/tasks/mosaic-r13.md`：GPT 可读的任务补充，仅含允许的事实/规则/指导。
- `robofrontier/suite/mosaic_policy_package.py` 与专用 build/check 脚本、专用测试：
  产出可审查的家族包，不通过修改公共启动器来硬编码这九项。
- 必要时新增 Mosaic 自有 skill 补充材料；通用 skill 的引用/装载方式等待公共整合，
  不把家族特例继续塞入共享 SKILL.md。

### 3.1 每项必须核对的字段

1. case_id、R13源版本、实际scene/资产hash、机器人数量与基座/朝向、桌面轮廓和
   高度、坐标轴/单位、相机标定、实际 READY 指令范围。
2. 方块60mm、质量/摩擦等需要公开的物理假设、格距81mm、正确图案与世界方向、
   四种颜色及图像、库存守恒；6×12、9×18、12×24分别列出。
3. L1的口袋开口/深度/底面；L2的3mm红线；L3无可见网格但目标坐标定义仍存在。
4. 与裁判逐项对照的公开完成条件：释放、稳定持续1s、颜色/一格一块、朝向；
   L2/L3中心xy5mm与z3mm、8度轴对齐；L1完整投影轮廓容纳、0.3mm包含余量、
   底面0.8mm与实际接触判据。数值必须从当前裁判/规格核对后登记，不手写另一套
   随意漂移的标准；稳定速度与双边界包含语义也在对应表中核对。
5. 供料归属不是独占控制权；允许安全交接、中央/桌面暂存和多臂并行；没有强制
   机器人配对、固定路线、固定颜色顺序或必须回home的屏障。
6. 失败/未知动作的处理、保留已有成品、释放与撤退的不同里程碑，遵守已有工具
   语义和观察合同，不添加 Oracle 专用恢复接口给 policy。

静态桌面/机器人几何与初始物体精确姿态、实时物体真值是不同公开边界；新增
字段按既定观察协议逐项审查。不要因为补任务说明就全量导出 private JSON。

允许指导 GPT 依据 RGB 与机器人反馈识别抓持、观察物体—夹爪偏移、考虑夹爪
开口与邻块干涉、安排交接/释放/退出、保护已完成格并滚动规划并行。
不得把 Oracle 私有 IK、轨迹坐标序列、repair recipe、隐藏物体真值或工程对话
直接变成初始 policy 经验。跨运行经验复用需要独立的实验声明。

### 3.2 新策略包就绪与展示步骤

先固定逐项证据索引和允许的公共事实 → 对照最终环境/裁判/工具 → 产出家族包及
差异报告 → 共享正式门禁/装载集成 → 生成新 run 的冻结输入供审查 → 再启动 GPT。

不得修改历史 frozen task、motion/source 或既有 Oracle report 的字节以把字段
改成 ready。建立侧车登记，明确哪一份资产/逻辑/控制组合有什么证据。
正式 GPT 所用模型、topology、观察/成本/运行协议另行冻结；旧1200s probe、旧
Oracle pilot 或展示倍速不能悄悄成为新实验限制。准备阶段与物理/推理启动分离。

回退，也不继续扩展；先登记其行为，再由整合负责人统一吸收。
不对其他 worktree 的未提交文件做修改、提交、重置或代合并。

建议顺序：各家族交付规格/证据和共享需求 → 冻结各分支待合并快照（包括明确选择的
未提交内容）→ 确定唯一公共格式与适配契约 → 整合一次公共基础设施 → 每家族做
输入/裁判/工具一致性检查 → 新策略 run 冻结 → GPT 仿真。

展示/文档改变不自动要求重跑整套 Oracle；资产、控制或裁判行为改变则重新做影响
分析和对应验证。控制指纹一致也不代表各次 Oracle 执行源码完全一致。

## 5. 多工位播放器应怎样工作

每个工位 i 保持自己的不可变记录 R_i、已审查保留区间 K_i、独立源时间映射、
展示速度 s_i、刚体变换 T_i，以及完成状态。全厂只共享输出帧号 k 和输出fps。

```text
全厂输出时间 τ = k / fps
对每个仍在播放的工位 i：
    从它自己的 edit 中取得该输出帧对应的原始状态序号和源时间 t_i
    将事件推进到 t_i（包括跨剪辑点的事件），恢复该工位真实记录姿态/外观
    用该工位自己的 T_i 放入工厂
对已经播放完的工位：保留精确最终姿态和最终外观，标记已完成
所有工位更新后设置全厂展示时钟 τ，再渲染一次工厂画面
```

不同桌子的源时间可以在同一个输出帧分别为20s、500s、9000s；不能共用一个源
时间或一张全局删帧表。当前 FactoryPlayback.apply 会写 data.time=t_i，未来
编排器须明确在各桌更新完后设置展示时钟，不能让最后更新的桌子决定全厂时间。

**用户已选 end_policy=hold_final**：全部从首帧开始，各自完成后停在最终成品；
工厂视频在最长轨迹完成时结束。允许已完成工位静止，不循环、不把各桌强行拉成
相同时长，不将播放循环或轨迹剪辑说成新的 Oracle 实验。

- 精确复现当前交付：直接消费各桌render_frames；Mosaic默认30倍速、30fps。
- 换倍速/帧率：从完整保留源状态重新采样；公共方案应明确采用连续剪后时钟的
  采样相位，避免每遇到剪辑点重启采样而累积时间偏差。已有逐帧映射仍保留作
  历史精确复现，不能在迁移时悄悄改掉已交付语义。
- 源状态、事件、编辑表、工厂工位与变换的hash全部绑定。新整合格式建议另升
  明确版本（例如v2），为现有几种v1提供明确转换/验收，不伪装成同一格式。
- 表/基座/机械臂/物体整体平移和水平旋转，尺寸/相对布局保持；任意重排或缩放
  不由旧轨迹担保。旧v6 Mosaic底座与实际R13不同，已知匹配版本是
  outputs/robo-factory/v6-mosaic-recorded-20261027，仍需各家族冻结源绑定。
- 高效读取/解码每个所需源块并缓存，按需FK；汇总所有工位姿态后只渲染一次。
  不是为每张桌子渲染整厂再拼接，不重跑物理/IK/接触求解。

## 6. 长期明显但无作用抖动：缺口与判定计划

**当前没有完成这一层。** 现有画面变化阈值会保留明显运动；“变化大就保留”
无法满足本次要求，而“机械臂不动就删除”又会误删有效持握/支撑/接触过程。
不能从qpos、指令中的force_n或未发生动作，声称实测机械力为零。

建议用原始轨迹和现存动作/事件/任务进展生成家族语义标签，再固化独立源时间表。
分类依据不依赖工厂背景像素，也不以渲染后剪整厂视频补救。

1. **保护有效过程**：实际搬运/有效机械臂或夹爪动作、抓取建立/释放、交接、物体
   有净位移/任务机构变化、失败与恢复关键时刻、进展/支持/资格/成功状态变化。
   静态支撑、力持握、稳定判定及得分dwell等可能有意义，不能仅因无位移删掉。
2. **识别候选无用段**：持续若干秒，任务相关机械臂无有效操作，物体只有局部来回
   振荡；累计路程大而净位移/趋势小，没有抓持关系、目标接近、任务进展或资格
   变化。使用位移/角度单位、滑动窗口、趋势/幅度/周期和进入退出滞回，不能只有
   一个速度阈值。具体阈值通过原片抽查校准，不在规划阶段声称已经验证。
3. **允许明显振荡被删**：幅度本身不能成为永久保留条件；需结合家族任务作用
   和保护区间判断。但有效的旋钮操作、寻找解、受控重抓、失败恢复或主动接触
   不能因为最终没有加分就自动归为无用振荡。
4. **分级审查**：确定无用→可删；确定有作用→保留；作用/力未知→标记待审查，
   不编造零力证据。对明确重复且无用的振荡可保留代表性首尾和关键结果，再
   压缩冗余部分；保留删留原因、源区间和审查记录。
5. **事件与因果**：跳过一段时仍恢复其后的正确外观和状态，保留必要转换帧，
   不插值穿过剪辑断点，不改原始执行时间/失败计数。原始任务成本/并行效率用
   完整记录评估，不能用去等待后的展示时长冒充实际效率。

原始记录足以支撑上述一部分离线分析；是否确有“无实测机械力”缺乏完整时间
序列时必须留未知。未来若需要关节力矩/接触力/支持资格遥测，作为共享录制扩展
单列字段、频率、单位与来源，合并后实现。旧记录不能凭空补造这些数据，也不
为了剪视频重跑整套 Oracle。

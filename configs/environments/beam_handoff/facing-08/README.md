# 实验三：八臂空中传递长木条（环境预览 v1）

八台 Franka Panda 分四列摆放，每列两臂隔桌相对。俯视图从左到右为 A/B、C/D、E/F、G/H；A/C/E/G 在南侧，B/D/F/H 在北侧。木条横跨桌宽，运输方向沿桌长向右。

| 参数 | 初始值 |
| --- | --- |
| 长桌 | 3.30 × 2.10 m，台面高 0.40 m |
| 相邻列基座间距 | 0.72 m |
| 面对面基座间距 | 1.70 m |
| 木条 | 长 1.20 m × 宽 45 mm × 高 45 mm |
| 木条质量 | 1.458 kg（密度 600 kg/m³） |
| 起点、终点中心 | 世界 X = −1.25 m、+1.48 m |

权威几何参数在 `parameters.json`。修改后重新生成环境；保存的 `initial` keyframe 是静置后的完整初始化。浅蓝背景、橡木色桌面、较深木纹长条；编号贴片、箭头和起终点边框不参与碰撞。木条是带 freejoint 的单一刚体，使用真实接触、重力和摩擦，没有吸附或抓取焊接。

构建：`.venv/bin/python -m scripts.build_beam_handoff`。

打开原生预览：`.venv/bin/mjpython -m scripts.view_beam_handoff`。F6 切换全局、俯视、另一全局和四列近景；F7 恢复初始状态。macOS 可能需 Fn＋F6/F7。

`task-draft.json` 记录目标和待验收规则：双臂支撑搬运、接收方支撑建立后发送方松手、掉落计失败且仅由发送方恢复，最终放入右端区域。初始发送方为 A/B；成功交接后才转移保管责任。若跌出可恢复范围，报告失败，不能自动复位或让接收方捡起来绕过交接。抓取位置、分组细节、顺序、姿态与并行策略没有固定解法。

`validation.json` 只检查加载、home IK、初始接触与静置稳定性，不是抓取或传递成功证明。最初预览阶段没有接 LLM 或增加策略工具；当前接入说明见下文。双臂是任务规则；尚未证明单臂物理上绝对不能搬运。

最初在相同尺寸、质量、摩擦与原位置夹爪参数下进行了两次 Oracle 抬升测试；两种抓取高度均滑脱，未进入交接。原模型在当前 45 mm 开口下闭合到零仅产生约 2.25 N 的腱驱动力／夹爪，不等于其 100 N 力上限。证据见 [初次 Oracle 工程报告](../../../../runs/beam-handoff-oracle-20261022/README.md)。

随后共享控制器补入显式 grasp 模式，用声明的抓取力／速度驱动模型，并先对初始抓点、接手、松爪和撤离做候选图搜索。物理验证 attempt-07 在原尺寸、原质量、原摩擦与 NoSlip 下完成 A/B→C/D→E/F→G/H 三次空中交接并最终放下。每 2 ms 的跨臂接触检查未记录碰撞；全部动作 60 次、仿真时间 251.12 s。抓取模式的软件驱动力包络为 70 N，没有增加原执行器硬上限。这是一个 Oracle 可行参考，未进行 GPT 试验、真机标定、恢复策略或所有路径的认证。[控制与规划工程记录](../../../../runs/beam-handoff-grasp-20261022/README.md)。


策略任务接入已提供 `task.json`，可由现有 `scripts.create_pipeline_run --task` 准备 Single、Coordinator/Workers、Peer 或 Adaptive 运行；准备不启动仿真或模型。仍保留 `task-draft.json` 作为设计说明。正式规则和阈值以每次冻结的 `task.json` 为准。

当前任务的私有验收记录空中支撑、接收与发送夹持重叠、保管责任、掉落/发送方恢复、跨臂碰撞及终点完整入区/释放/稳定。双侧正接触力和空中保留是声明的支撑代理，不能证明每臂承担了多少重量。途中掉落计失败尝试，合法恢复后可继续；接收方违规拾取、未验证交接和超容差碰撞使合规性失败。交接重叠和短暂接触丢失均采用公开固定阈值，不向策略返回实时真值或分数。最后落桌只在完整进入目标区且此前保持支撑时例外，不接受 Agent 自报阶段豁免。

已有 23 个固定视角（两全局、top、四个 pair 近景、八臂各 front/side）；Agent 自选观察。初始几何和机器人本体信息公开，过程物体真值/Oracle 路线不公开。新的 action_batch 只保证本次命令同周期启动，不保证同到达或共同持物稳定。是否使用检查、批次或 fork 由策略决定；每个角色仍只能操控自己拥有的机器人。


2026-10-23 接入补充：公开 task.json 现包含完整评分后果和两条规划风险提示；与私有验收共用事件定义。action_batch 的可选 sync_group 允许不同角色各自提交自己的当前命令，参与名单/期限一致、提交齐且重新校验后同周期启动；等待不占用无关机器人。Single、Adaptive、Coordinator/Workers、Peer 共用执行路径，Coordinator/Meta 仍没有物理控制权限。这是协议能力对齐，并非四种模型策略或真机同步控制已验证。
